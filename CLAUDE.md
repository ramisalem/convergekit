# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Development
make dev              # Start all apps in watch mode (web + api + worker via Turborepo)
make install          # Install all pnpm workspace dependencies

# Code quality
make build            # Build all apps and packages
make lint             # Run ESLint across all packages
make typecheck        # Run TypeScript type checking across all packages

# Infrastructure
make docker:up        # Start PostgreSQL (pgvector) + Redis via Docker Compose
make docker:down      # Stop services

# Database
make db:generate      # Generate Drizzle migration files from schema changes
make db:migrate       # Apply pending migrations
make db:studio        # Open Drizzle Studio in the browser

# Run tests (only db package has tests currently)
pnpm --filter @convergekit/db test
pnpm --filter @convergekit/db test:watch

# Target a specific package
pnpm --filter @convergekit/<package> <script>
```

## Architecture

**Turborepo monorepo** with pnpm workspaces. Three apps consume shared packages.

### Apps

| App | Framework | Port | Purpose |
|-----|-----------|------|---------|
| `apps/web` | Next.js 15 + React 19 + Tailwind CSS 4 | 4000 | Frontend — fumadocs-based wiki UI with next-intl i18n |
| `apps/api` | Hono (Node) | 4001 | REST API — all routes under `/api`, auth via better-auth sessions or Bearer tokens |
| `apps/worker` | BullMQ workers (Node) | — | Background job processor — clones repos, chunks/embeds code, generates wikis |

### Packages

| Package | Purpose |
|---------|---------|
| `@convergekit/db` | Drizzle ORM schema + query helpers. PostgreSQL with pgvector. Exports: `.` (queries), `./schema` (table types), `./client` (db connection) |
| `@convergekit/ai` | AI utilities: model selection, embeddings, tree-sitter code chunking (TS/JS/Python/Go/Rust/Java), encrypted API key helpers |
| `@convergekit/queues` | BullMQ queue instances + job data types. Import queues here; worker consumes them |
| `@convergekit/auth` | better-auth setup with GitHub OAuth and Drizzle adapter |
| `@convergekit/config` | Zod-validated env vars via `@t3-oss/env-core` |
| `@convergekit/types` | Shared Zod schemas and inferred TypeScript types |
| `@convergekit/mcp` | Model Context Protocol server implementation |

### Data model (key tables)

`repositories` → `branches` → `documents` → `chunks` (with `embedding` vector + `searchVector` tsvector for hybrid search)

`repositories` → `wikiPages` (section/page hierarchy generated by the wiki worker)

`userAiSettings` stores per-user provider selection + AES-256-GCM encrypted API keys.

`mcpTokens` stores SHA-256 hashes of bearer tokens scoped to a repository.

### Job pipeline

1. **repository-analysis** (priority 1): Clone repo, parse + chunk code with tree-sitter, generate embeddings → stored in `chunks`
2. **incremental-update** (priority 2): Re-process changed files between two commits
3. **mind-map** (priority 3): Generate a repository mind map JSON stored as a special `__mindmap__` wiki page
4. **wiki-generation** (priority 3): Use mind map + file tree → generate TOC via LLM → write individual wiki pages via vector-search-grounded LLM calls
5. **translation** (priority 3): Translate document content to a target language

Bull Board UI available at `/api/admin/queues` when the API is running.

### API route structure

All routes are under `/api`. Public: `/health`, `/auth`. Protected (session): `/repositories`, `/documents`, `/chat`, `/jobs`, `/notifications`, `/settings`, `/wiki`. MCP (scoped token): `/mcp`. Admin: `/admin/queues`.

### Frontend patterns

- `apps/web/src/lib/api-client.ts` — typed Hono RPC client used for all API calls
- `apps/web/src/lib/use-job-progress.ts` — SSE hook for real-time job progress
- i18n routing via next-intl; locale prefix on all routes
- Wiki pages rendered with fumadocs + remark-gfm + Mermaid diagram support

## Code style

- **Prettier**: no semis, single quotes, trailing commas, 100-char print width (`prettier-plugin-organize-imports` runs on save)
- **ESLint**: no floating promises, consistent type imports required (`import type { ... }`)
- **TypeScript**: strict mode, `verbatimModuleSyntax` — always use `import type` for type-only imports
- better-auth table columns (`user`, `session`, `account`, `verification`) must not be renamed — the adapter depends on exact column names
- Chunk embeddings are 3584-dim (nomic-embed-code); pgvector HNSW index exists but sequential scan is used for high-dim queries
